# Отчёт по проекту MEXC Indicator (версия 1.3.0)

> **Обновление (после установки зависимостей):** `npm install && npm test` выполнены на Node 22 с настоящими Express и dotenv — все тесты, включая `api.http.test.js` и `pages.http.test.js`, проходят (сейчас 122 вместе с проверкой smoke-скрипта). Пункты «Не проверено» ниже про Express и заглушку dotenv больше не актуальны; реальный MEXC, MongoDB и внешний вид в браузере по-прежнему не проверялись.

Я добавил в терминал MEXC набор технических индикаторов, перенёс часть индикаторов из проекта `rinar_bot`, написал для них автотесты и обновил документацию (README, DEMO.md, Swagger). Это продолжение прошлой работы: исправления хранения истории BID/ASK (раздел 3) остаются в силе.
Часть проверок я не смог выполнить: в моей среде нет сети (`npm install`, MEXC, браузер). Что именно не проверено — в разделе 2.

## 1. Что добавлено

**Индикаторы** (кнопка «ƒ Индикаторы» в шапке терминала, выбор запоминается в браузере, данные обновляются раз в 15 с):

| Индикатор | Откуда | Где на экране | Таймфрейм |
|---|---|---|---|
| EMA 20, SMA 50, SMA 200 | классика | поверх свечей | любой |
| Полосы Боллинджера (20, 2) | классика | поверх свечей | любой |
| DEMA ATR Channels 40/15 | `rinar_bot` (`dema_atr.py`) | поверх свечей | любой |
| Rinar: уровни (зелёная, жёлтая, фиолетовая, оранжевая, красная, RSI 25D, RSI 14W) и метки медвежьей дивергенции MACD 64/270/9 | `rinar_bot` (`indicators.py`) | поверх свечей | только 1D |
| RSI 14 (по Уайлдеру, уровни 30 и 70) | `rinar_bot` (`breadth.py`) | отдельная панель | любой |
| MACD 12/26/9 с гистограммой | классика | отдельная панель | любой |

**Сервер**
* `src/services/indicators.js` — чистые функции расчёта, без сети и состояния.
* `src/services/indicator.service.js` — каталог, проверка совместимости индикатора с таймфреймом, запрос 500 свечей у MEXC для прогрева, отдача последних `limit` баров.
* Новые эндпоинты: `GET /api/indicators/catalog` и `GET /api/indicators?symbol=&interval=&names=&limit=`. У `GET /api/klines` появился параметр `limit` (1–500, по умолчанию 200, как было).
* Swagger обновлён до 1.3.0: новые пути, схемы ответов (`IndicatorsResult`, `IndicatorOutput` и др.), параметр `limit` для свечей.

**Интерфейс**
* Меню индикаторов с группами; недоступные на текущем таймфрейме пункты (Rinar вне 1D) заблокированы с подсказкой.
* Линии поверх свечей с легендой и последними значениями; метки дивергенции на свечах.
* RSI и MACD — отдельные панели под BID/ASK; все графики листаются и масштабируются синхронно. Панели не пересоздаются при обновлении, меняются только серии.
* Устаревший ответ (пользователь успел сменить пару или таймфрейм) отбрасывается.

## 2. Что проверено, а что нет

**Проверено (94 теста проходят, `npm run test:unit`)**
* **Формулы против оригинала.** Rinar (все 7 линий, включая недельную RSI-поддержку), DEMA ATR, RSI, MACD, Bollinger, EMA/SMA и дивергенция MACD сверены с Python-кодом `rinar_bot` на 450 синтетических дневных свечах (эталон `tests/fixtures/rinar-golden.json`). Расхождение не превышает ~5·10⁻¹³ (относительное), сигналы дивергенции совпали бар в бар, в том числе при параметрах 12/26/9, где сигналов больше.
* Свойства: границы RSI 0–100, порядок зон Rinar, окна SMA/EMA, схлопывание полос Боллинджера на константе.
* Сервис: каталог, отказ при несовместимом таймфрейме, неизвестном индикаторе, лишнем числе индикаторов; обрезка до `limit`; запрос ровно 500 свечей нужного интервала.
* Контроллеры (без Express): коды 400 и 502, граница `limit`, отсутствие обращений к бирже при неверных параметрах.
* Скрипт терминала исполняется в Node с заглушками DOM и графиков: загрузка сохранённого выбора, блокировка Rinar вне 1D, включение на 1D с метками, панели RSI/MACD, отсутствие пересоздания панелей при обновлении, очистка, синхронизация осей.
* Swagger ↔ роутер, все `$ref`, границы параметров; статическая проверка шаблонов.

**Не проверено**
* `tests/api.http.test.js` (в нём теперь и новые тесты `/api/indicators`) и `tests/pages.http.test.js` требуют Express, которого в моей среде нет. Прогоните `npm install && npm test`; если что-то упадёт, пришлите вывод.
* Реальные запросы к MEXC. Для часового интервала биржа, насколько мне известно, использует обозначение `60m`, поэтому `1h` я перевожу в `60m`; это не проверено на живом API. Лимит 500 свечей на запрос взят как заведомо допустимый.
* Внешний вид. Скрипт страницы выполнялся только на заглушках графиков, в настоящем браузере с lightweight-charts я его не открывал. Цвета, высота панелей и расположение легенды требуют беглого взгляда глазами.
* MongoDB (`history.mongo.js`) по-прежнему не запускалась: ни базы, ни `mongoose` в моей среде нет.
* Для запуска тестов в моей среде понадобилась временная заглушка пакета `dotenv`; в архив она не входит.

## 3. Исправления из прошлой итерации (история индикатора BID/ASK)
* Запись не чаще одной точки на пару за 5 секунд, сколько бы вкладок ни было открыто.
* Потолок размера коллекции и периодическое удаление самых старых записей (при настройках по умолчанию порядка 100 МБ, цифра оценочная).
* Резервный буфер в памяти: индикатор работает без MongoDB и при её переполнении.
* Любая открытая пара пишется в фоне (до 10 пар, забывается через сутки без просмотров).
* Время точки совпадает с границей свечи; `limit` отдаёт самые новые точки; фильтр торгуемых пар понимает статусы `"1"` и `"ENABLED"`.

## 4. Найденная по ходу работы ошибка
Кнопка 1H в терминале отправляла интервал `60m`, а валидатор принимал только `1h`: часовой график отвечал ошибкой 400. Теперь принимаются оба написания, наружу уходит `60m`.

## 5. Ограничения и что не перенесено
* Индикаторы Average RSI (корзины альтов и топ-40) не перенесены: им нужны свечи десятков монет.
* Ончейн-индикаторы (CVDD, MVRV, SOPR) не перенесены: данные берутся не из API MEXC.
* Торговые правила и бэктест `rinar_bot` не переносились — только расчёт линий и сигнал дивергенции.
* Rinar считается по всем свечам, включая текущую незакрытую (в оригинале расчёт идёт по закрытой дневной свече), поэтому последняя точка линий дрейфует в течение дня.
* Историю BID/ASK до первого запуска сервера восстановить нельзя; без MongoDB она теряется при перезапуске (как раньше).
